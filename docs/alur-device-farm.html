Loupe memantau komentar pull request. Satu komentar /farm <layar> menjalankan build dari head SHA PR di simulator iOS atau emulator Android lokal, lalu mengirim hasilnya kembali ke PR.

Alur lengkap

Hanya dua hal yang menyeberangi batas mesin: komentar yang masuk, dan hasil yang keluar. Capture, device, dan artefak seluruhnya di satu Mac.

Antrean dan beberapa perangkat

/farm login --all membuat satu job untuk setiap perangkat terdaftar yang sesuai platform PR. WebKitDemo memilih simulator iOS yang tersedia, termasuk yang belum boot; WebViewDemo memilih emulator Android online. Tanpa --all, satu job dijalankan oleh satu perangkat.

Satu perangkat menangani satu job, maksimal delapan perangkat terdaftar. Perangkat sibuk menyelesaikan antreannya. Kedua platform bisa bekerja bersamaan dari PR masing-masing. Build SHA sama dibagikan; build berbeda pada checkout yang sama diproses bergantian. Artefak disimpan terpisah per SHA.

Unggah dan pemulihan koneksi

Publikasi diserialkan per repository. Setiap percobaan memeriksa ulang branch, SHA file, dan marker komentar. Gangguan koneksi, timeout, atau HTTP 500/502/503/504 dicoba ulang maksimal dua kali, setelah 1 dan 2 detik. Error izin token tidak diulang otomatis.

Satu komentar hasil per PR dan commit, dengan entri per layar dan perangkat. Identitas perangkat lama dimigrasikan agar tidak menjadi entri tambahan. Jika retry tetap gagal, hasil lokal dipertahankan beserta pesan error.

Build dikunci ke commit

Farm mengunci head SHA PR saat komentar terdeteksi, lalu mencari manifest untuk SHA itu. Tidak ketemu berarti farm membangunnya sendiri: clone, checkout commit itu, build melalui Xcode (iOS) atau Gradle (Android), salin artefak ke folder per SHA, daftarkan manifest — baru menyentuh device.

Penguncian ke SHA disengaja: screenshot harus membuktikan kode PR, bukan kode apa pun yang kebetulan ada di disk. Commit yang sudah pernah dibangun dipakai ulang, jadi hanya /farm pertama di sebuah commit yang membayar beberapa menit; sisanya hitungan detik.

Kegagalan compile tidak pernah membuka sesi device. Run gagal dengan output alat build yang asli. Manifest yang artefak .app atau .apk-nya sudah terhapus dibangun ulang, bukan gagal di device.

Layar yang tidak muat satu layar

*Batas default 4 bagian, maksimum konfigurasi 6. Halaman yang lebih panjang dari batas ini dapat terpotong; potongan tidak dijahit menjadi satu gambar.

Screenshot Appium adalah layar device, jadi konten di bawah lipatan tidak ikut. Farm memotret, melakukan flick cepat di tepi kanan, memotret lagi, dan berhenti saat frame tidak berubah lagi — layar yang muat menghasilkan tepat satu bagian.

Perbandingan frame memakai ambang 0,2%, bukan kesamaan byte. Antialiasing dan indikator yang berkedip menggeser 0,008% byte, sementara scroll sungguhan menggeser setiap baris — jarak 25× antara noise dan sinyal. Bagian-bagiannya berbagi satu entri galeri, dan run yang menghasilkan lebih sedikit bagian menghapus bagian lama di branch, jadi tidak ada file yatim yang menyesatkan.

Ambang itu ditemukan lewat kegagalan, bukan dirancang. Versi pertama memakai kesamaan byte persis dan menghasilkan dua bagian untuk halaman yang jelas-jelas muat. Baru setelah selisihnya diukur — 737 byte dari 9.043.128 — terlihat bahwa yang dibandingkan adalah derau, bukan konten.

Jaminan tanpa duplikasi

Komentar hasil dan file gambar sama-sama idempoten per commit SHA. Marker tersembunyi di badan komentar yang menentukan POST atau PATCH; blob sha yang menentukan buat-baru atau timpa.

Hitungan nyata di PR #1, diverifikasi lewat API GitHub setelah tiap perintah. PR dan branch artifact-nya sudah dibersihkan setelah PoC selesai, jadi angka di bawah adalah catatan pengukuran, bukan sesuatu yang masih bisa dibuka:

Baris ketiga pernah salah. Pengulangan menghasilkan 3 entri karena dedup memakai run id, padahal komentar baru selalu membawa id baru. Unit test luput karena memberi retry id yang sama — bentuk yang tidak pernah terjadi di dunia nyata. Sekarang dedup per layar, dan test-nya sudah dipastikan gagal terhadap kode lama.

/farm tanpa parameter ditolak dan tercatat sebagai kartu rejected. Nama yang tidak dikenal ditolak sebelum menyentuh device. Komentar di dalam code block atau quote diabaikan total, supaya diskusi tentang perintahnya sendiri tidak memicu run.

Yang sudah terbukti

  • Rantai penuh dijalankan dengan token asli di PR sungguhan — bukan mock, bukan payload buatan.
  • Capture iOS dan Android, scroll local-demo, serta publikasi di PR kedua demo telah diverifikasi. Dua simulator dan satu emulator berjalan paralel.
  • Commit yang belum punya build dibangun sendiri oleh farm, lalu dipakai ulang pada run berikutnya.
  • Gambar di branch artifacts terjangkau publik: HTTP 200, image/png, ukuran identik dengan file lokal.
  • Run yang menghasilkan lebih sedikit bagian menyapu sisa bagian lama di branch, terbukti lewat commit penghapusan yang asli.
  • Run membaca publishing selama posting berlangsung dan completed setelah capture selesai. Jika unggah tetap gagal setelah retry, PNG lokal tetap tersedia dan detail Publishing menampilkan error.
  • Setelan baru sampai ke instalasi yang confignya sudah ada, tanpa menimpa pilihan pengguna.
  • 98 test — GitHub, Appium, dan tiap alat build dimock — plus smoke test yang menjalankan UI Electron sungguhan.
  • /farm web menangkap cacat asli WebKitDemo: alert app-bound domain, karena WKAppBoundDomains dideklarasikan tanpa limitsNavigationsToAppBoundDomains. Perbaikannya ada di sisi app, bukan Loupe.
